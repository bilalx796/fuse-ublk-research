# Run 1 Method — 2026-10-31 (4-hour node window)

Node: pc800.emulab.net, Xeon E5-2630 v3, 2 sockets x 8 cores x 2 SMT (32 CPUs), 62 GiB, kernel 6.8.0-147.
Approved by user this session: building ublksrv + libfuse, loading modules / virtual devices,
fio on virtual devices (B setups, exception to the no-raw-device-fio rule), performance governor.

## Setups
| ID | Stack | Notes |
|---|---|---|
| B0 | /dev/nullb0 | null_blk, 8 GiB, blk-mq, 8 submit queues, irqmode=0 (inline completion), memory_backed=0 (discards). Null-device baseline, not "fastest storage" |
| B1 | /dev/ublkb0 | ublksrv 1.9 (6d0d922) null target, 4 queues x depth 128 |
| B2 | /dev/ram0 | brd RAM disk, 8 GiB |
| B3 | /dev/ublkb1 | ublksrv loop target, backing /dev/ram0, direct I/O to backing, 4 queues x depth 128 |
| F0 | ext4 on /dev/ram1 | mkfs defaults, no lazy init |
| F1 | passthrough_hp (libfuse 3.14.0 example) on F0 | conventional FUSE; kernel FUSE passthrough not available on 6.8. Default options (multi-threaded, splice on, caching on) |
| F2 | ext4 on /dev/ublkb1 | created after B3 (mkfs overwrites B3's data) |

## CPU placement
- fio: CPUs 0,2,4,6 (NUMA node 0, distinct physical cores), `cpus_allowed_policy=split`.
- Servers (ublk queue threads, FUSE daemon threads): CPUs 8,10,12,14 (node 0).
  ublksrv sets its own queue-thread affinity from the blk-mq map (observed on CPUs 4, 11, 19 — fio's CPU
  and NUMA node 1), so `scripts/pin-server.sh` overrides it after device creation.
- SMT siblings (N+16) left idle but SMT is on.
- Governor: performance on all CPUs (was schedutil).

## Measurement choices
- **Total latency** (`lat_percentiles=1`, lat_ns), not clat. null_blk and brd complete inline at submit,
  so clat reported ~0.17 µs in the smoke test and hid the real cost (~2.6 µs total on null_blk).
- **CPU per I/O is system-wide** (review point D): /proc/stat busy-jiffy delta over each run
  (user+nice+sys+irq+softirq+steal, all CPUs), scaled by 20/25 to exclude ramp, divided by I/Os.
  Includes fio, the server and kernel threads. Resolution: 10 ms jiffies over 25 s, fine for this.
  Idle background not subtracted (to measure).
- Context switches per I/O: /proc/stat ctxt delta, same scaling.

## Smoke test (3 s, 4k randread qd1, clat p50 — before the latency fix; for sanity only)
nullb0 307k IOPS, ublkb0 54k, ram0 303k, ublkb1 46k; ext4 randwrite 145k, FUSE randwrite 12k (p50 69 µs).

## Known limitations of this run
- Single node, single boot, no reboot between setups.
- passthrough_hp defaults (caching on) interact with O_DIRECT; FUSE knob sensitivity not explored.
- B3 − B2 and F2 − F0 include the loop target's own work (review point C).
- ublk loop does a second I/O into brd from userspace; FUSE does a second I/O into ext4. So the F/B
  comparisons are "interface + userspace backend", not interface alone. B1 − B0 is the cleanest
  interface-only number we have for ublk; there is no FUSE null-fs equivalent in this run.
